# 服务器协议转换

把**普通 Minecraft 服务器**(例如 mc244.com, 原生 TCP 协议)转换为**本地 `wss://` 端点**,
让 MCJS 这类浏览器端客户端可以直接连上去。

原因很简单: 浏览器里跑的 MC 客户端只能通过 WebSocket 通信, 而且页面如果是 https,
就必须是 `wss://`(混合内容会被拦)。本工具在本机开一个 WebSocket 服务,
把收到的帧还原成原始 TCP 字节流, 再转发给真正的 Minecraft 服务器, **反向亦然**。

```
MCJS (浏览器)
    │  wss://127.0.0.1:8443        ← WebSocket(已 TLS 加密)
    ▼
服务器协议转换(本工具, 仅监听 127.0.0.1)
    │  TCP mc244.com(:SRV 解析)    ← 原样转发的字节流
    ▼
mc244.com / 任意普通 Minecraft 服务器
```

转发过程默认**不解析、不修改任何游戏数据包**(唯一例外是自动识别到的浏览器端客户端,
见下面说明, 以及可选开启的"握手地址改写", 默认关闭)。

### 浏览器端客户端(MCJS 这类)的协议翻译

MCJS 用的是 **EaglercraftX 系协议**: 它**不发原版握手包**, 而是先发一段自己的握手
(版本协商 → 请求登录 → 允许登录 → 完成登录), 之后才是原版 1.8.8 的游戏数据。
原版服务器看不懂开头那几帧, 表现就是"刚连上就断线"。

本工具内置翻译层, 会自动认出这种客户端并代答整段握手:

```
浏览器客户端                    本工具                        原版服务器
────────────                    ──────                        ──────────
EaglercraftX 握手  ────────→  代答握手, 挑协议版本
                              │
                              └──── 原版握手 + 登录开始 ────→
                              ←──── 登录成功 / 踢出原因 ─────
允许登录 + 完成登录 ←────────┘
原版 1.8.8 游戏数据 ←────────→  双向搬运 + 封帧/压缩互转
```

细节: 代答需要目标服务器是**离线模式 + 1.8.x(协议 47)**, 因为浏览器端客户端只会 1.8。
服务器要求**加密握手**时, 翻译层会自己代客户端做完(RSA 换共享密钥, 之后全程
AES-128-CFB8) —— 很多服务器开着加密握手但并不真的去 Mojang 校验会话, 离线名字照样放行;
如果服务器确实要正版, 它给的踢出原因会**原文**转给客户端, 不会干巴巴地断开。

翻译层自己说的话都带前缀(中文界面 `[协议转换器] `, 英文界面 `[Protocol Adapter] `), 服务器说的话不带 —— 一眼就能分清是谁在说话。

**封帧差异(最容易踩的坑)**: 原版 TCP 是 `[VarInt 包长][包体]` 的字节流, 一个 TCP 段里可以塞很多包;
浏览器客户端却是**一个 WebSocket 帧 = 一个完整的裸包(包 id + 内容)**, 既没有长度前缀, 也没有压缩
(它读帧时直接拿帧的开头当包 id 读)。所以翻译层必须**逐包拆帧**: 服务器来的每个包单独发一帧,
客户端来的每一帧单独装回原版字节流。要是把原版字节流整段塞进一帧, 客户端会把长度前缀当成包 id,
表现就是"登录成功但一直卡在加载界面", 约 10 秒后客户端自己超时断开(它的加载界面有 200 tick 超时)。

> 网页版客户端一般没有正版账号, 所以默认目标给的是 `mc244.com` 这类**离线模式**服务器;
> 真正的正版验证服务器(如 Hypixel)在加密握手之后仍会拒绝没有会话的客户端, 本工具不参与认证。

> 加密握手那一步需要 `cryptography` 库(打包好的 EXE 里已经带上了; 从源码跑就
> `python -m pip install cryptography`)。没有这个库时, 遇到需要加密的服务器会明确提示,
> 其它情况照常工作。

## 1. 快速开始

### 方式一: 用打包好的 EXE(推荐)

1. 双击 `dist\服务器协议转换.exe`(若只有源码, 先按第 6 节打包)。
2. 界面里确认 **转发目标**(默认 `mc244.com`, 不带端口时按 SRV 记录找服务器), 点 **启动服务**。
3. 点 **安装到系统信任库**(见下面第 4 节), 然后**重启浏览器**。
4. 在 MCJS 客户端的服务器地址栏填:

   ```
   wss://127.0.0.1:8443
   ```

   然后连接。日志窗口会显示 `#1 WSS 接入 127.0.0.1:xxxxx -> mc244.com [默认目标]`。

### 方式二: 从源码运行

需要 Python 3.8+(Windows 官方安装包自带 tkinter):

```bat
python -m pip install fastapi uvicorn        :: 桥接层(WebSocket 监听 + HTTP 状态页)
python -m pip install cryptography           :: 可选: 目标服务器要求加密握手时才会用到
python main.py
```

### 方式三: 命令行(无界面)

```bat
python main.py --no-gui --target mc244.com --port 8443
python main.py --no-gui --language zh           :: 中文界面/日志(默认 English)
python main.py --check          :: 检查证书 + 目标服务器连通性
python main.py --check-update   :: 查一次云端最新版本(退出码 1 = 有新版本)
python main.py --install-cert   :: 生成并导入证书
```

## 3. 配置项(config.json)

界面里的改动会自动保存到程序目录下的 `config.json`, 也可以直接编辑或用命令行覆盖。

| 键 | 默认值 | 说明 |
| --- | --- | --- |
| `listen_host` | `127.0.0.1` | 监听地址。**默认只监听本机**, 改成 `0.0.0.0` 会暴露到局域网 |
| `wss_port` | `8443` | `wss://`(TLS)端口 |
| `ws_port` | `8080` | `ws://`(明文)备用端口, `0` 表示关闭。仅当 MCJS 页面本身是 `http://` 时才可能用到 |
| `target` | `mc244.com` | 转发目标。支持 `host`(按 SRV 解析)、`host:port`、`mc://host:port`、`[IPv6]:port` |
| `routes` | `{}` | 路径映射, 例如 `{"/mc244": "mc244.com", "/本地": "127.0.0.1:25565"}`。界面里不提供输入框, 需要就改这里 |
| `use_srv` | `true` | 目标**不带端口**时先查 `_minecraft._tcp.<域名>` 的 SRV 记录(与原版客户端一致), 查不到回落 25565 |
| `rewrite_handshake_host` | `false` | 把握手包里的服务器地址改写成真实目标域名。客户端填的是 `127.0.0.1:8443` 时, 部分服务器会按地址校验或分流从而拒绝连接, 这时打开它 |
| `eagler_translate` | `true` | 浏览器端客户端(EaglercraftX/MCJS 系)协议翻译: 自动识别对面是不是这种客户端, 认出后由本工具代答握手。关掉就退化成纯字节转发 |
| `server_brand` | `MCJS-Proxy` | 浏览器客户端(及其服务器列表)看到的**服务器品牌**。界面里不提供输入框, 需要就改这里或命令行 `--server-brand` |
| `server_brand_version` | (空) | 同上, 服务器版本; 留空 = 用程序版本号。命令行 `--server-version` |
| `spoof_brand` | `vanilla` | 登录完成后向目标服务器声明的**客户端标识**(`MC\|Brand`)。原版 1.8.8 客户端发的就是 `vanilla`; 留空 = 不发。命令行 `--spoof-brand` / `--no-spoof-brand` |
| `tls_enabled` | `true` | 是否启用 wss |
| `cert_dir` | `certs` | 证书目录(相对程序目录) |
| `cert_common_name` | `localhost` | 证书 CN |
| `cert_extra_names` | `[]` | 证书 SAN 里要额外包含的名称/IP, 例如 `["192.168.1.5", "mypc"]` |
| `cert_days` | `3650` | 证书有效期 |
| `cert_generator` | `auto` | `auto` / `python`(内置纯 Python 生成) / `openssl` |
| `connect_timeout` | `10.0` | 连接目标服务器的超时秒数 |
| `heartbeat_sec` | `30` | WebSocket 心跳间隔, `0` 关闭 |
| `max_payload_mb` | `16` | WebSocket 单帧上限 |
| `log_level` | `info` | `debug` / `info` / `warn` / `error` |
| `language` | `en` | 界面/日志/玩家提示语言: `en`(English) 或 `zh`(中文)。命令行 `--language` |
| `update_check` | `true` | 启动时向 `update_url` 查一次最新版本(见下面"云端版本检查")。命令行 `--no-update-check` |
| `update_url` | `https://banbengengxinjiancha.pages.dev/version.json` | 版本检查地址, 可以写多个(逗号/空格分隔, 按顺序试, 第一个能应答的生效), 留空 = 不做检查。命令行 `--update-url` |

### 云端版本检查

启动时本工具会用一次普通的 HTTPS GET 向 `update_url` 查询最新版本(超时 20 秒, 失败只在日志里记一行, 不影响使用)。
发现比当前版本新时, 窗口标题下方会出现一行提示, 点它用浏览器打开下载页面; **帮助 → 检查更新** 可以随时手动查一次。
程序自己不会下载文件, 只把页面交给浏览器。

端点只要返回这样一份文档就行(Cloudflare Worker / 静态文件都可以), 下载页字段可有可无,
多出来的字段(比如以后加 `sha256`)会被旧版本直接忽略; 字段名 `download_page` / `page` / `url` / `download_url` 都认:

```json
{
  "version": "1.1",
  "download_page": "https://example.com/download"
}
```

`version` 也接受 `v1.1` 这类写法, 比较时只看数字部分(`1.1` = `1.1.0`); 应答是纯文本(`1.1` 一行)也能识别。
请求头带 `User-Agent: wss-proxy (ServerProtocolBridge/<版本号>)`, 公开端点可以据此过滤掉扫描器(UA 里带 `wss-proxy` 的请求通过)。

**国内可达性**: `*.workers.dev` 在国内会被 DNS 污染(解析到国外 IP, 连接超时), 而 `*.pages.dev` 不会,
所以版本文件放在 **Cloudflare Pages** 上(纯静态, 不需要 Worker / 限流; 工程就在旁边的 `..\版本更新检查\`)。
同一个 Pages 站点里也放一份 `服务器协议转换.exe`, 提示里的链接就是**自己的直链**(见第 6 节), 不经过第三方网盘。
`update_url` 支持写**多个地址**(逗号或空格分隔), 按顺序试, 第一个能应答的生效 —— 换地址时把国内能通的写在前面
即可。全都连不上时程序只记一行日志, 不影响使用。
命令行:

```bat
python main.py --check-update                    :: 查一次并退出(退出码 1 = 有新版本, 2 = 检查失败)
python main.py --no-gui --update-url https://... :: 换一个检查地址(也可以直接改 config.json)
python main.py --no-gui --no-update-check        :: 启动时不做检查
```

## 4. 信任证书(wss 的关键一步)

`wss://` 需要证书。本工具启动时会自动签发一张自签名证书到 `certs\cert.pem`
(SAN 包含 `localhost`、`127.0.0.1`、`::1` 和本机主机名), 但**浏览器默认不信任自签名证书**,
所以必须导入一次:

* **图形界面**: 点 **安装到系统信任库**(等价于下面的命令)。
* **命令行**:

  ```bat
  certutil -user -addstore root certs\cert.pem
  ```

  或 PowerShell(静默, 不弹窗):

  ```powershell
  Import-Certificate -FilePath certs\cert.pem -CertStoreLocation Cert:\CurrentUser\Root
  ```

* 之后**重启浏览器**。Chrome / Edge / IE 使用 Windows 证书库, 导入即生效。
* **Firefox 使用自己的证书库**, 需要单独导入:
  设置 → 隐私与安全 → 证书 → 查看证书 → 导入 → 选 `certs\cert.pem`,
  并勾选"信任由此证书颁发机构来标识网站"。

如果要用局域网 IP 或别的域名访问(例如 `wss://192.168.1.5:8443`),
在 **证书 → 额外名称** 里加上它, 再点 **重新生成证书** 并重新导入。

## 5. 常见问题

**Q: 客户端连不上, 提示证书错误 / `ERR_CERT_AUTHORITY_INVALID`**
没导入证书或没重启浏览器, 按第 4 节做一次。

**Q: 连上了但马上被踢掉**
先看日志。浏览器端客户端(MCJS 这类)会被自动识别, 日志里会出现:

```
#1 检测到浏览器端客户端 (EaglercraftX 握手), 启用协议翻译层
#1 浏览器端客户端握手: 品牌 EaglercraftX u53 | 支持握手协议 [3, 4, 5] | 支持游戏协议 [47] | 开启验证 否
#1 客户端请求登录: 用户名 xxx | 客户端填写的服务器地址 'wss://127.0.0.1:1000' | 密码 无
#1 目标服务器登录成功: xxx (UUID ...), 已通知客户端允许登录
#1 协议翻译完成, 进入游戏数据直通
```

走到最后一行说明协议这一层已经通了。常见卡点:

- `本代理只支持 Minecraft 1.8.8 (协议 47)`: 目标服务器的版本不是 1.8.x。
  换一个 1.8 服务器(或让服务器装 ViaVersion 之类支持旧版本)。
- 日志里有 `已代做加密握手`: 目标服务器要求加密, 代理已经代客户端做完这一步。
  之后如果被踢, 踢出原因就是服务器自己的原话(例如真的正版验证失败), 那说明它确实要正版账号。
- 日志里有 `目标服务器要求加密握手, 但本机没有可用的 AES 库`: 从源码跑的话装一下
  `python -m pip install cryptography`(或用打包好的 EXE, 里面已经带了)。
- `目标服务器拒绝登录: <原因>`: 服务器自己的原因(白名单、封禁、人满、正在重启等), 原因原文已转给客户端。
- 消息前缀 `[协议转换器] ` 是代理自己说的; 没有前缀的都是服务器原话。
- 卡在 `已选择握手协议 ... 等待客户端登录请求`: 客户端没继续发登录请求, 通常是被页面脚本拦住, 换浏览器试试。
- 日志已经走到 `协议翻译完成, 进入游戏数据直通`, 但客户端一直停在加载界面、约 10 秒后自己断开:
  说明回程封帧不对(客户端要的是"一个帧一个裸包")。跑一遍 `python tools/check_frames.py` 就能定位。

如果你是**原版客户端**直连(没走浏览器), 日志里是原版握手包:

```
#1 握手包: 协议版本 767, 客户端填写地址 "127.0.0.1:1000", 下一步 登录(Login)
```

- `客户端填写地址` 是客户端把握手包里的服务器地址填成了本地代理地址。多数服务器不看它,
  但**部分服务器会按地址校验或按域名分流**, 表现就是"刚连上就断"。
  这种情况勾上 **高级 → 按目标域名改写握手地址**(或 `--rewrite-handshake-host`), 重新连接。
- 日志里出现 `Outdated client!` / `你使用的版本过旧`: 客户端协议版本与服务器不匹配, 与本工具无关。
- 在线模式(正版验证)服务器会要求登录账号, 日志里会看到服务器发回的加密请求或直接断开。
- 日志里出现 `心跳超时`: 客户端所在环境把 WebSocket 心跳帧丢了, 把 `heartbeat_sec` 调大或改成 `0` 试试。

**Q: 怎么确认"协议翻译"这一层真的没问题**
跑 `python tools/check_frames.py`(可以加 `--seconds 30`)。它会像真实客户端那样完成握手, 然后把代理
发回来的**每一帧**都当成一个完整的 1.8 包去解析: 包 id 必须在客户端方向的合法范围内、内容要正好读完,
才算通过。全绿就说明客户端能正常解析这些数据; 有可疑帧时它会把帧内容打出来, 一眼能看出问题在哪。
(需要代理正在运行; 默认读 `config.json` 里的监听地址, 也可以 `--url wss://127.0.0.1:1000` 指定。)

**Q: 想改目标服务器看到的"客户端标识", 或客户端列表里显示的"服务器品牌"**
`config.json` 里: `spoof_brand`(发给目标服务器的 `MC|Brand`, 默认 `vanilla`, 留空 = 不发; 代理会在登录完成后
按原版客户端习惯补发这一条, 并丢弃浏览器客户端自己发的那条, 免得被反作弊/统计插件一眼认出)、
`server_brand` / `server_brand_version`(浏览器客户端及其服务器列表看到的服务器身份)。
命令行等价参数: `--spoof-brand` / `--no-spoof-brand` / `--server-brand` / `--server-version`。

**Q: 界面语言怎么切**
基本设置第一行的"界面语言"下拉框选 English / 中文即可, 立即生效并记进 `config.json`; 命令行用 `--language zh`。

**Q: 目标填错 / 服务器不在线时会怎么样**
客户端会收到一条**带原因**的提示(`[协议转换器] ...`), 而不是干巴巴的 "Connection Closed";
日志里也会写明是 DNS 解析失败、连接被拒绝、超时还是握手失败。转发目标留空会被直接拒绝(不会静默回退到默认地址)。

**Q: 客户端发文本帧(base64)时数据丢了**
现在的版本会自动切换 base64 模式并兼容**省略 `=` 补齐**、URL-safe 字符表以及带换行的写法;
如果日志出现 `文本帧不是有效的 base64, 已丢弃 N 字节`, 会把内容开头一起打出来, 把这行发我即可。

**Q: 日志显示"连接目标服务器失败"**
目标地址写错、端口被墙, 或者 DNS 解析不到。先用 `python main.py --check` 验证连通性。

**Q: 只能填 `ws://127.0.0.1:8080` 吗**
`ws://` 也能用(明文), 但如果 MCJS 页面是通过 https 打开的, 浏览器会以"混合内容"为由拦截,
只能走 `wss://` —— 所以默认开启 8080 端口只是为了方便排查问题。

**Q: 会影响我的账号吗**
本工具不保存任何凭据: 原版客户端模式下只是原样搬运字节; 浏览器端客户端模式下,
翻译层只处理连接开头的握手与封包长度/压缩, 游戏内容不落盘。

**Q: 能同时连多个服务器吗**
可以。在 `config.json` 里用 `routes` 做路径映射(界面里没有输入框, 需要就手动改配置), 例如:

```json
"routes": {
  "/mc244": "mc244.com",
  "/本地": "127.0.0.1:25565"
}
```

对应 `wss://127.0.0.1:8443/mc244`、`wss://127.0.0.1:8443/本地`。每条连接各自独立建立 TCP 连接。

## 6. 打包成 EXE

```bat
python tools\build.py
```

流程: `PyInstaller(onefile) → UPX 压缩 → MPRESS 压缩 → 冒烟验证`, 产物在 `dist\`:

| 产物 | 说明 |
| --- | --- |
| `dist\服务器协议转换.exe` | 主程序(带控制台: 可以用 `--no-gui` / `--check` 等命令行参数) |
| `dist\MPRESS-folder\服务器协议转换.exe` | MPRESS 压缩版(体积更小, 备选) |
| `dist\build-report.txt` | 各阶段体积与 SHA256 |

打包脚本会把桥接层的动态依赖一并收进去(`--collect-all uvicorn` / `--collect-all websockets` /
`--hidden-import httptools`), 否则打出来的 EXE 会出现"WebSocket 监听起不来"。

要点:
* PyInstaller 打包时通过 `--upx-dir` 已经把 `python3x.dll`、tcl/tk 等内部文件用 **UPX** 压缩过一遍;
  之后脚本还会对 EXE 本身再压一次, 并**跑冒烟测试**, 一旦压缩导致无法启动会自动回退到未压缩版本。
* MPRESS(v2.19)处理 64 位程序需要 `-x` 参数, 脚本已带上; 结果不可用时不会保留该文件。
* 无控制台的纯 GUI 版: `python tools\build.py --windowed`。
* 压缩包被杀软误报是这类 PE 加壳的通病, 遇到时把文件加入白名单即可。

## 8. 实现要点

* **透明转发**: WebSocket 二进制帧的负载就是 Minecraft 协议字节; 反向从 TCP 读到的字节也原样塞进帧里。
* **协议翻译(可选, 默认开)**: 上行的第一个数据帧按 EaglercraftX 首个握手包解析, 成功才启用翻译层
  (`proxy/translator.py`), 认不出就完全按原样转发 —— 原版客户端不受任何影响。翻译层里:
  * 在客户端面前扮演 EaglercraftX 服务端, 在服务器面前扮演原版 1.8.8 客户端;
  * **一个帧一个裸包**: 浏览器客户端读帧时直接拿帧开头当包 id(没有长度前缀, 也没有压缩),
    所以服务器来的每个包单独发一帧, 客户端来的每一帧单独装回原版 `[包长][包体]` 字节流;
    多个包拼进一帧客户端只会认第一个, 带长度前缀的字节流塞进一帧则会让整条流错位;
  * 客户端发来的注入消息帧(v5 起皮肤/扩展走这条路, 以 `0xEE` 开头)直接丢弃, 它不是原版包;
  * 握手期间服务器已经发来的游戏数据先缓存, 等客户端"完成登录"后再一起下发(同样一帧一个包);
  * 服务器启用压缩后由代理解压/再压缩, 客户端方向始终不压缩(参考实现也不给浏览器端发 `Set Compression`);
  * 压缩阈值在解析途中就该生效 —— 真实服务器会把 `Set Compression` 和下一个包塞进同一个 TCP 段,
    所以上行的解码是"一个一个取包"( `Decoder.next_packet` ), 而不是一次解析一整段;
  * 客户端发往 `EAG|...` 私有通道的插件消息直接丢弃(原版服务器不认识);
  * 服务器要加密握手时代客户端做完: 用服务器给的 RSA 公钥加密随机共享密钥与验证令牌,
    之后两个方向的 TCP 字节流全程 AES-128-CFB8(`proxy/crypto.py`);
  * 代理自己给客户端发的提示都带 `[协议转换器] ` 前缀, 服务器原话不加 —— 便于区分;
  * 客户端在登录请求里没带合法名字时, 依次回退到握手包里的 `authUsername`、最后才是内置备用名。
* **离线 UUID**: 与 Java 的 `UUID.nameUUIDFromBytes("OfflinePlayer:"+名字)` 完全一致, 保证客户端、代理、
  目标服务器三边看到的玩家 UUID 相同。
* **不启用压缩**: 握手响应里不返回 `Sec-WebSocket-Extensions`, 浏览器就不会用 permessage-deflate, 帧里保持原始字节。
* **背压**: 两个方向都用阻塞式 `sendall`, 对端慢下来时自然反压, 不会把内存撑爆。
* **分片与控制帧**: 完整实现 RFC 6455 的分片消息、ping/pong、关闭握手与协议错误处理。
* **base64 兼容模式**: 少数老浏览器客户端会把数据放进文本帧, 程序会自动切换到 base64 模式, 也能识别 `Sec-WebSocket-Protocol: base64`。
* **证书**: 无第三方库, 用标准库手写 DER 编码 + RSA 密钥生成 + PKCS#1 v1.5 签名; 系统里有 openssl 时会优先用 openssl(更快)。测试里包含真实 TLS 握手校验(域名与 IP 两种 SAN)。
* **只监听 127.0.0.1**: 默认不对外开放。改成 `0.0.0.0` 等于把转发入口暴露给整个局域网, 请自行评估。
* **语言与注释**: 代码注释一律英文; 界面、日志、发给玩家的提示都通过 `proxy/i18n.py` 的 `tr()` 取词
  (词条在 `proxy/locales/`), 默认 English、可切中文 —— 协议层文案(例如 `[协议转换器] ` 前缀)也跟着语言走。
* **客户端标识伪装**: 进入游戏后, 代理按 `spoof_brand` 主动补发一条 `MC|Brand`(原版客户端就是这么干的),
  并丢弃浏览器客户端自己发的那条, 目标服务器侧的插件因此看到的是一个普通客户端。补发时要按连接当前的
  压缩状态正确封帧 —— 多封一层就会被对端当成别的包解, 直接踢线。
* **桥接层(FastAPI + uvicorn)**: 监听套接字由本模块自己 `bind`+`listen` 后交给
  `uvicorn.Server.serve(sockets=[...])`, wss 与 ws 各跑一个 daemon 线程、共用同一个 FastAPI app;
  WebSocket 负责双向转发, `GET /` 是状态页、`GET /status` 是 JSON。
