What it does

The relay is deliberately small. It handles the transport and handshake work a browser cannot do, then gets out of the way.

It is not a VPN and it does not change your IP. A local server stays local; a public server stays public.

Listener wss://127.0.0.1:8443 by default; the plaintext fallback is ws://127.0.0.1:8080.
Transport One process. TLS, binary frames, subprotocols and the closing handshake are handled by websockets; compression is off.
WebSocket clients Handshakes from clients that support wss:// or ws:// are answered locally. Classic Java clients pass through.
Java login SRV lookup like the vanilla client; a login acknowledgement is sent for 1.20.2+ targets when the browser client does not send one.
Accounts Offline by default. Microsoft sign-in uses the device-code flow. A compatible third-party account service can be added with the API root from its provider.
Certificate A self-signed certificate is created on first run and can be installed into the Windows trust store.
Web UI A loopback-only control panel at http://127.0.0.1:8765 for start/stop, settings, logs, accounts and certificates. The desktop window is the same UI in a native webview.
MCP The same listener exposes /mcp over JSON-RPC 2.0 and Streamable HTTP, with 39 tools, resources and prompts for AI clients.
Server list Every list query goes to the target live. There is no status cache, so the MOTD, player count and version are current; a slow target makes that one query wait.
Not included No anti-cheat bypass, no movement rewriting, no packet pacing, no cloud relay.

What's in this build v—

The 2.x line adds a browser control panel and an MCP endpoint, so the same relay can be configured by hand or driven by an AI client. The relay core stays small: game data is forwarded unchanged.

Control from the browser

The Web UI listens on http://127.0.0.1:8765 by default. Start and stop the relay, edit forwarding settings, read logs, manage accounts and install the certificate from one page. A password is optional and only allowed when the UI is bound to a non-loopback address.

MCP for AI clients

The same listener serves /mcp over JSON-RPC 2.0 and Streamable HTTP. It exposes 39 tools for status, configuration, logs, accounts, certificates and updates, plus resources and prompts. Loopback clients need no key; remote clients use an MCP key.

Sign-in and certificates

Offline accounts need no sign-in. Microsoft sign-in uses the device-code flow with a built-in public client ID; credentials refresh before every server join. A self-signed certificate is created on first run and can be installed into the Windows trust store.

A smaller gateway

FastAPI, uvicorn and the ASGI layer are gone. HTTP status pages and game traffic run directly on websockets, which handles TLS, binary frames, subprotocols and the closing handshake. Compression is off, and client data is forwarded unchanged.

Run it

The Windows build is a single EXE. The first run creates a certificate and starts a local listener; nothing is installed as a service.

  1. Download and run

    Start the EXE. SmartScreen will warn because the build is unsigned; choose More info → Run anyway.

  2. Set the target

    Enter the Java server address in the app. SRV records are used when the address has no port.

  3. Connect the browser client

    Use wss://127.0.0.1:8443 in any client that accepts a wss:// address. The plaintext fallback is ws://127.0.0.1:8080.

  4. Join the server

    Start the relay and connect. The app shows the handshake and any kick reason as readable text.

From source

The source package is a Python project; it also runs on Linux and macOS. Unzip it and install the dependencies:

Control and automation

The desktop window is the Web UI in a native webview. Open the same address in a browser, or point an MCP client at /mcp:

http://127.0.0.1:8765
http://127.0.0.1:8765/mcp
curl -s http://127.0.0.1:8765/mcp \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'

Both are loopback-only by default. A Web UI password can only be set on a non-loopback bind; remote MCP requires an MCP key.

Requirements: Windows 10/11 x64 and the Microsoft Visual C++ Redistributable. The native window uses the system Edge WebView2 runtime; the Web UI works in any current browser.

Notes and limits

The short version: this is a local transport relay, not a cheat, a VPN, or a hosted service.

Anti-cheat

Movement packets are not rewritten, transaction probes are not answered, and idle position packets are not sent. A server-side anti-cheat that is sensitive to jitter can still flag a connection through any relay; this build does not try to work around that.
