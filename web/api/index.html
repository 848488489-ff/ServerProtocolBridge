Static JSON

Field reference

Seven read-only JSON files serve the release page, the FAQ and the desktop updater. There is no key, no account and no server-side code; the host returns the files as they are.

Base URL /api/ · UTF-8 · CORS * · Cache-Control no-store · no auth.

Endpoints

Path Returns
/api/version.json Release manifest: version, date, size, download and source links.
/api/faq.json Bilingual FAQ items rendered by the release page.
/api/features.json Feature catalogue; the current release page does not load it.
/api/stats.json Static platform, runtime, port, protocol and client facts.
/api/licenses.json Third-party components and their licences.
/api/site.json Site metadata and links to every endpoint.
/api/endpoints.json Machine-readable index of these seven files.

Runtime REST API (/api/v1/)

The running program exposes an automation JSON API under /api/v1/ on the Web UI listener. Every operation maps to an MCP tool, so scripts and curl can control the program exactly the way an MCP client does.

Authentication matches the MCP endpoint: loopback (127.0.0.1) is free; a non-loopback caller must present the MCP key as Authorization: Bearer <key>, X-MCP-Key: <key> or X-API-Key: <key>. With no key set the API is open only when the Web UI password is off.

Method Path Notes
GET/api/v1/Discovery: name, version and the full tool catalogue.
GET/api/v1/docsIn-program bilingual documentation page (English by default, switchable).
GET/api/v1/statusCurrent service state, version, listeners and traffic counters.
GET/api/v1/configRead the live configuration (passwords and tokens are omitted).
POST/api/v1/configWrite configuration fields; the body is the config object or {"config": {...}}.
POST/api/v1/service/startStart the proxy with the current configuration.
POST/api/v1/service/stopStop the proxy; the Web UI and MCP endpoint stay up.
POST/api/v1/service/restartStop then start again with the current configuration.
GET/api/v1/logsRead the in-memory log; query since/level/limit.
POST/api/v1/logs/clearClear the in-memory log.
GET/api/v1/toolsList every MCP tool (name, description, inputSchema).
POST/api/v1/tools/<name>Call any MCP tool by name; the body is the arguments object or {"arguments": {...}}.

Examples

# status
curl -s http://127.0.0.1:8765/api/v1/status

# set the forwarding target and start
curl -s -X POST http://127.0.0.1:8765/api/v1/config \
  -H 'Content-Type: application/json' \
  -d '{"target": "mc.example.com:25565"}'
curl -s -X POST http://127.0.0.1:8765/api/v1/service/start

# remote automation needs the MCP key
curl -s http://host:8765/api/v1/status \
  -H 'Authorization: Bearer YOUR_MCP_KEY'

Conventions

The same rules apply to every file under /api/.

  • Every endpoint is a GET request. There are no writes or authenticated routes.
  • Responses are UTF-8 JSON. Fields may be added; clients should ignore unknown fields.
  • No key, account or cookie is required. The static host returns the file directly.
  • JSON responses send Access-Control-Allow-Origin: * and Cache-Control: no-store.
  • Replacing a JSON file publishes the change; there is no service to restart.
  • version.json is the single source of truth for release metadata. The page shows an error state, not a bundled fallback, when it cannot be read.

version.json

Read by the release page and the desktop updater. Only version is required; unknown fields are ignored, so the schema can grow without breaking older clients. The values below are illustrative; the source fields are filled in after the archive is built.

{
  "version": "2.7.0",
  "download_url": "/downloads/Server%20Protocol%20Bridge.exe",
  "page_url": "https://banbengengxinjiancha.pages.dev/",
  "min_version": "1.1.0",
  "force_update": false,
  "release_date": "2026-11-07",
  "changelog": "One line per changelog entry.",
  "changelog_en": "One line per changelog entry.",
  "file_size": 20257998,
  "source_url": "/downloads/ServerProtocolBridge-2.7.0-source.zip",
  "source_name": "ServerProtocolBridge-2.7.0-source.zip",
  "source_version": "2.5.0",
  "source_size": 477640,
  "source_updated": "2026-11-06T11:25:09Z"
}
Field Type Notes
versionstringNewest published version, compared with the running build.
download_urlstringDirect link to the Windows build. Empty hides the download button.
page_urlstringRelease page opened by the desktop updater when download_url is a static build path.
min_versionstringOldest build still supported; older clients are asked to update.
force_updatebooleanMarks the release as mandatory for older clients.
release_datestringRelease date, preferably YYYY-MM-DD.
changelogstringDefault release notes. One line per entry.
changelog_enstringEnglish release notes used when the interface is English.
file_sizenumberWindows build size in bytes.
source_urlstringDirect link to the source ZIP. Empty hides the source button.
source_sizenumberSource ZIP size in bytes.
source_namestringSource ZIP filename shown in the button tooltip.
source_versionstringVersion inside the source package.
source_updatedstringUTC timestamp of the last source export.

The updater accepts http:// and https:// links and resolves same-site relative paths against the manifest URL. A missing optional field never blocks a running session.

faq.json

The release page fetches this file once and renders every item in both languages. Switching the language does not make another request.

Field Type Notes
versionnumberSchema version for this document.
updatedstringLast content update date.
itemsarrayOrdered FAQ entries.
items[].idstringStable identifier.
items[].questionobjectObject with en and zh strings.
items[].answerobjectObject with en and zh strings, rendered as text.

Other files

These files are descriptive. The current release page does not need them to render, but they remain public for tools and older versions.

  • features.json — version and a bilingual item list (id, title, body).
  • stats.json — platform, runtime, listener, Web UI/MCP endpoints, protocol, client and language facts.
  • licenses.json — runtime components, standard-library modules and licence names.
  • site.json — project name, version, tagline, base URL and a link map.
  • endpoints.json — base path, count and the seven endpoint records.
